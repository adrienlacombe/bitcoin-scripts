# u32 word arithmetic

Represents a 32-bit word as four byte-valued stack items. The module provides
addition, subtraction, comparison, Boolean operations, shifts, rotations, and
stack manipulation. `u32_conditional_negate` adds normalized conditional sign
routing for a byte-word.

- **Position:** the main local byte-oriented backend for SHA-family and
  RIPEMD-family constructions.
- **Evidence:** `locally-reproduced`, including exhaustive byte-level logic tests.
- **Tradeoff:** operation fragments are moderate, while a reusable Boolean table
  occupies 256 stack items.
- **Representative results:** add is 78 bytes; subtract is 77; unsigned
  less-than is 38; conditional negate is 83; direct zero testing is 4.
  Canonical compressed-u32 decoding is 431 bytes with a 7-item peak; checked
  four-bit extraction is 73 bytes with a 5-item peak; canonical byte validation
  is 12 bytes with a 4-item peak. Little-endian bit conversion is 514 bytes
  with a 35-item peak. Conditional selection is 9 bytes with a 9-item peak
  and a 10–30-byte canonical nine-item witness.
- **Narrow decoder:** canonical nonnegative compressed-u32 decoding is a
  smaller domain-specific alternative to the full signed decoder; it accepts
  only `0..=0x7fffffff` and rejects negative or aliased ScriptNums.
- **Lane comparison:** the checked byte-equality mask is 149 bytes with an
  11-item peak and returns four independently addressable equality bits for
  two hostile u32 words; it uses no table or hints.
- **Lane ordering:** the checked byte-less-than mask is 149 bytes with an
  11-item peak and returns four independently addressable ordering bits for
  two hostile u32 words; it uses no table or hints.
- **Lane projection:** the checked byte high-bit mask is 133 bytes with an
  8-item peak and returns four packed lane bits without a lookup table or
  hints; it is a compact alternative when a caller needs only byte MSBs.
- **Checked-rotation question:** can the existing seven-bit rotation accept
  hostile byte-word witnesses safely with a small adapter? The minimal answer
  validates all four limbs with `verify_canonical_byte()`, temporarily routes
  them through the alt stack, and reuses `u32_rrot7()`. It is 130 bytes with an
  8-item peak, versus 76 bytes unchecked; the representative witness is
  9 bytes and the four maximal canonical byte items serialize to 13 bytes.
- **Zero-test question:** can a u32 zero predicate avoid constructing a second
  zero word for `u32_equal()`? The local answer folds four per-limb zero tests
  with `OP_BOOLAND`, reducing the fragment from 21 bytes to 4 under the same
  compilation policy.
- **Zero-test boundary:** the four limbs are supplied in the existing u32
  representation; no hints are required, and callers must enforce canonical
  byte limbs when witnesses are hostile.
- **Zero-byte mask result:** `u32_to_zero_byte_mask()` checks the four canonical
  limbs and packs their zero predicates into one numeric `0..=15` mask. It is
  67 bytes with an 8-item peak for a four-item all-`0xff` witness, trading four
  extra peak items for per-byte information.
- **Shift question:** can a byte-aligned logical right shift avoid the generic
  u32 mask/table path while retaining a canonical hostile-witness boundary?
- **Shift hypothesis:** direct byte scheduling plus one inserted zero is
  smaller and shallower than the generic shared-table bitwise shift when the
  amount is exactly eight.
- **Shift comparison:** compare `u32_rshift8_checked()` with the generic
  `u32_shr(8, ...)` boundary, including table setup when it is required, and
  keep four data items and zero hints explicit. On that boundary, the direct
  path is 62 bytes with a 7-item peak; the generic path is 561 bytes with a
  272-item peak, including its 256-item XOR table and setup/cleanup.
- **Shift threat model:** malformed byte widths, raw aliases, negative values,
  and out-of-range limbs are hostile; the output must preserve unrelated main
  and alt-stack state.
- **Shift execution class:** locally reproduced in the strict tapscript-context
  executor; deployment remains `unclassified`.
- **Byte-left-shift question:** can the mirrored byte-aligned logical left
  shift use the same canonical boundary without a bitwise table or extra hints?
- **Byte-left-shift hypothesis:** direct byte scheduling plus one inserted zero
  should remain below the generic table-backed shift path for amount eight.
- **Byte-left-shift comparison:** compare the checked direct fragment with the
  existing generic shift after including table setup/cleanup, four data items,
  zero hints, and the same strict stack boundary. The direct path measures 56
  bytes and a 7-item peak; the table-backed boundary is 561 bytes and 272
  items.
- **Byte-parity question:** can one shared byte table expose four byte-local
  parity bits without paying for whole-word popcount accumulation?
- **Byte-parity hypothesis:** returning the four lookup results directly should
  save the accumulation tail while preserving the existing four-byte boundary.
- **Byte-parity comparison:** compare the checked projection with
  `u32_popcount()`, keeping the 256-item table, four data items, zero hints, and
  strict output cleanup explicit.
- **Consumers:** SHA-1, SHA-256, RIPEMD-160, and SHAKE256.

The compressed-wire addition experiment is documented separately in
[compressed total-domain u32 addition](u32-compressed-add.md). It saves witness
width but is dominated for locking-script bytes by the ordinary byte-word
adder.

The canonical nonnegative decoder is a domain-specialized variant of the full
signed decoder. It accepts only `0..=0x7fffffff`, consumes one canonical
ScriptNum, and returns four byte limbs. Its 405-byte policy-compiled fragment
uses a 6-byte maximum witness, reaches a 7-item strict tapscript peak, and
executes 328 fragment opcodes on the `0x7fffffff` fixture. It is
`locally-reproduced` with deployment `unclassified`; the range and canonical
checks are part of the fragment, while terminal predicates and transaction
context are excluded.

## Checked seven-bit rotation

The research question is whether a fixed seven-bit right rotation can become a
safe standalone fragment when every byte limb arrives as hostile witness data.
The hypothesis is that four existing canonical-byte checks are sufficient and
that the unchecked rotation can remain the only arithmetic implementation. The
comparison objective is the 76-byte unchecked `u32_rrot7()` fragment; the
checked adapter trades 54 locking bytes for input canonicality.

The fragment consumes four most-significant-byte-first limbs and returns their
right rotation by seven bits. It preserves unrelated main-stack and alt-stack
items. Every input must be a minimally encoded ScriptNum representing `0..=255`;
raw aliases, negative zero, negative values, and values above 255 fail before
rotation. It has no hint items and no terminal predicate or clean-stack
obligation of its own.

The threat model treats all four witness limbs as hostile. The measured
boundary is fragment-only: validation, rotation, and the temporary four-item
alt-stack route are included; witness pushes, output checks, transaction
context, and unrelated live state are excluded. The local tests use the pinned
`bitcoin-scriptexec` tapscript interpreter with the strict 1,000-item combined
stack limit, so the result is `locally-reproduced` and `unclassified`, not a
claim of consensus or relay-policy validation. The deterministic tests cover
1,000 random words, every limb position with known raw aliases and out-of-range
encodings, and preservation of surrounding main/alt-stack state.
